# Anise ZMK config

ZMK firmware for the Anise split keyboards. Firmware is built only by GitHub
Actions — there is no local toolchain, and `west` is not installed. Never try to
build locally; push and read the CI result.

## Core workflow

Editing a keymap and getting firmware is always this loop:

```bash
# 1. edit config/boards/shields/<shield>/<shield>.keymap
git add config && git commit -m "keymap: ..." && git push
# 2. wait for CI
gh run watch $(gh run list --limit 1 --json databaseId --jq '.[0].databaseId') --exit-status
# 3. download
gh run download --name firmware --dir zmk
```

Verify a change actually compiled the way you intended by grepping the job log
for the Kconfig it should have produced, rather than assuming:

```bash
gh run view --job <id> --log | grep -oE "CONFIG_[A-Z_]+=y" | sort -u
```

## Hard constraints

**Binding count must equal transform position count.** Bindings are a flat array
indexed against the `matrix-transform` in `<shield>.dtsi`. A surplus binding is
silently dropped and a missing one leaves the tail unbound — ZMK does not error.
Check before pushing:

```bash
PYTHONPATH=tools/pagegen python3 tools/pagegen/parse.py > /dev/null
```

**Presets are generated.** `anise60b_{win,mac,vim,hhkb}` come from
`tools/pagegen/make_presets.py`. Edit the `PRESETS` dict and regenerate; never
hand-edit those shields. A change to `anise60b`'s keymap flows into every preset
unless that preset pins the position explicitly.

**Both halves need flashing** when a change affects both, and a key only exists on
one half — check the column before telling anyone which file to flash. Columns 0–6
are the left half, 7+ the right.

## Gotchas

- **The two controllers are not interchangeable, and the failure looks like a dead board.** `anisectlp_01` and `anisectlc_10` map the `anise_ctl` connector to entirely different GPIOs. Wrong firmware gives you USB enumeration and Bluetooth advertising with *zero* working keys, because the matrix scans unconnected pins. If someone reports "it's detected but nothing types", suspect this before touching the keymap.
- **On macOS, a failed-looking copy is a successful flash.** `Error -36` in Finder, or `fcopyfile failed: Input/output error` with `cp`, is the board rebooting the instant it has the full image. The volume disappearing is the success signal — if the copy were rejected, the drive would still be mounted. Use `cp -X`; Finder writes AppleDouble metadata the bootloader's FAT volume chokes on.
- **Zero scan events means hardware, not keymap.** ZMK logs `Sending event at r,c` from the kscan driver, *before* the transform and keymap run. A keymap bug still produces that line. No line at all means the matrix never saw the key — no config change can fix it. See `diagnosing.md`.
- **Do not switch to zmkfirmware's reusable build workflow.** It targets the Zephyr 4.1 board layout; `config/west.yml` pins ZMK to a Zephyr 3.0 fork, and its ZMK-compat check fails against it. The hand-rolled matrix in `.github/workflows/build.yml` is deliberate.
- **`<shield>_left.conf` and `<shield>_right.conf` are symlinks** to the shared `<shield>.conf`. Editing "just the left half's config" is not possible without replacing the symlink.
- **A new preset shield needs its own `boards/` directory.** Zephyr resolves `boards/<board>.overlay` relative to the shield being built. Without copies, the RGB `led_strip` node is missing while `CONFIG_ZMK_RGB_UNDERGLOW=y` is inherited, and `rgb_underglow.c` fails to compile.
- **Never upgrade the bootloader.** The boards run Adafruit nRF52 with SoftDevice S140 6.1.1, which places the app at `0x26000`. A newer bootloader moves it to `0x27000` and every `.uf2` here stops working with no error.
- **`anise85a` and `anise85n` have a known extra binding** on three layers each. It is pre-existing and harmless (ZMK drops it). Do not "fix" it without deciding whether the transform is short a position or the keymap has a stray entry.

## The keymap page

`https://anisehid.github.io/zmk-config/` is regenerated by CI from the `.keymap`
sources on every push to `main`. Rebuild it locally with:

```bash
PYTHONPATH=tools/pagegen python3 tools/pagegen/build.py
```

`docs/` is git-ignored on purpose — committing it would let the published page
drift from source, which is the exact problem it exists to prevent.
